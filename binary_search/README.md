# Binary Search — Алгоритм бинарного (двоичного) поиска

Репоизторий представляет собой реализацию классического алгоритма бинарного поиска на языке Go. Бинарный поиск — это эффективный метод поиска заданного значения в **отсортированном** массиве (или коллекции), работающий по принципу «разделяй и властвуй».

## Принцип работы алгоритма

Алгоритм значительно быстрее линейного поиска, так как на каждом шаге он исключает из рассмотрения ровно половину элементов массива.

1. Инициализация: Устанавливаются две границы области поиска: левая (`left = 0`) и правая (`right = len(array) - 1`).
2. Цикл поиска: Пока левая граница не превысит правую (`left <= right`):
    * Вычисляется индекс среднего элемента: `mid = (right + left) / 2`.
    * Если значение в ячейке `mid` равно искомому, поиск успешно завершен.
    * Если искомое значение **меньше** среднего, правая граница сдвигается: `right = mid - 1`.
    * Если искомое значение **больше** среднего, левая граница сдвигается: `left = mid + 1`.
3. Результат: Если цикл завершился, а элемент не найден, алгоритм возвращает `-1` (или специальный флаг отсутствия).

> **Важное условие:** Алгоритм применим **строго** к предварительно отсортированным структурам данных. Если массив не отсортирован, результат работы будет непредсказуемым.

---

## Сложность алгоритма

| Критерий | Временная сложность | Описание |
| :--- | :--- | :--- |
| **Best Case** (Лучший случай) | $O(1)$ | Элемент находится ровно посередине массива при первом же шаге. |
| **Average Case** (Средний случай) | $O(\log n)$ | Требуется логарифмическое количество делений массива пополам. |
| **Worst Case** (Худший случай) | $O(\log n)$ | Элемент находится в самом конце уменьшающейся области или отсутствует. |
| **Space Complexity** (Затраты памяти) | $O(1)$ | Итеративная реализация использует константный объем дополнительной памяти. |
