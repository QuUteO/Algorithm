# Selection Sort — Сортировка выбором

Репозиторий представляет собой реализацию классического алгоритма сортировки выбором (Selection Sort) на языке Go. Это простой, интуитивно понятный, но относительно неэффективный алгоритм сортировки на месте (in-place), который обычно используется для обучения или на небольших объемах данных.

## Принцип работы алгоритма

Алгоритм разделяет массив на две части: уже отсортированную (в начале) и еще не отсортированную (в конце). На каждом шаге алгоритм находит минимальный элемент в неотсортированной части и меняет его местами с первым элементом этой части.

1. Поиск минимума: Просматривается неотсортированная часть массива (начиная с индекса `0` до `n-1`), чтобы найти элемент с наименьшим значением.
2. Обмен (Swap): Найденный минимальный элемент меняется местами с первым элементом неотсортированной части.
3. Сдвиг границы: Граница отсортированной части сдвигается на один элемент вправо.
4. Повторение: Процесс повторяется для оставшейся неотсортированной части массива, пока не будет пройден весь массив.

## Сложность алгоритма

| Критерий | Временная сложность | Описание |
| :--- | :--- | :--- |
| **Best Case** (Лучший случай) | $O(n^2)$ | Даже если массив изначально отсортирован, алгоритм всё равно выполнит все вложенные циклы для поиска минимума. |
| **Average Case** (Средний случай) | $O(n^2)$ | В среднем количество сравнений остается квадратичным. |
| **Worst Case** (Худший случай) | $O(n^2)$ | Худший случай (например, массив отсортирован в обратном порядке) требует того же количества сравнений. |
| **Space Complexity** (Затраты памяти) | $O(1)$ | Сортировка происходит «на месте» (in-place), дополнительная память не выделяется. |

> **Важное свойство:** Количество операций **обмена** (swap) у этого алгоритма минимально и составляет всего $O(n)$, что делает его эффективным в системах, где запись в память стоит значительно дороже, чем чтение.
